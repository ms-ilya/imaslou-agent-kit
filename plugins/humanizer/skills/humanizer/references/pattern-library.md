# Pattern Library

## How this library works

**Preservation takes precedence over every pattern below.** Keep all substantive claims, uncertainty, attribution, numbers, dates, units, limits, logical relationships, and enumeration members. Do not invent specificity or remove content to satisfy a style rule. Only content-free filler, redundant restatement, unwanted chatbot scaffolding and clearly extraneous interface residue may be removed without an explicit abridgment request. Protected content and the requested editing scope remain unchanged. The before/after pairs are synthetic instructional illustrations, not factual reports or measured performance results.

These patterns are **context-sensitive editorial heuristics**. An actionable finding identifies a passage and a concrete problem with clarity, repetition, organization, genre, or the source's voice. A word, punctuation mark, three-item grouping, or similar sentence length alone is not a finding. Keep a legitimate construction when it serves the text; a rewrite is not required for every match.

**Evidence status:** Tiers identify catalog groups, not acceptance gates, reader-impact priority or confidence in machine authorship. Review organization and substantial problems before vocabulary and typography, regardless of ID. This library supplies no calibrated detector probabilities, language-wide frequency claims or validated texture targets. Examples do not establish detector improvement.

English examples and vocabulary prompts apply to English segments. For Russian and other languages, review clarity and structure in the source language and its intended register. Do not apply English word lists through translation or impose English punctuation and contraction habits. Preserve technical terms and language-appropriate grammar.

**Inline vs. referenced split:** Short pattern prompts stay inline. Patterns 1, 4, 6, 7, 8, 9, 11, 16, 17, and 19 link to `<skill-dir>/references/ai-tells-lexicon.md`; Pattern 2 links to `<skill-dir>/references/vocabulary-by-era.md`. Reference matches require the same contextual judgment and preservation checks as the patterns here.

## TIER 1: Core catalog group

Review these patterns when they create an identifiable problem. Legitimate instances may remain.

### 1. Specificity over vagueness

**Review when:** Inflated description or repeated praise obscures what the supplied text actually says. Vague attribution may need clarification, but it is still part of the claim.

Consider significance claims, lists of media mentions, unnamed authorities, and promotional adjectives in context. Use concrete details only if the input supplies them. Preserve substantive assessments and every supplied attribution or citation; do not replace several media mentions with an invented interview. If a source is unnamed, retain that limitation or flag it separately instead of creating a name or date.

**Vocabulary prompts:** See Pattern 1 in `<skill-dir>/references/ai-tells-lexicon.md`.

**Before:**
> Industry reports suggest that the new dashboard may make reports easier to access, underscoring its potential to improve access.

**After:**
> Industry reports suggest that the new dashboard may make reports easier to access.

The tail repeats the access claim. The attribution remains vague because the supplied text does not identify the reports. Both attribution and uncertainty survive; no source or access-time measurement is invented.

### 2. Vocabulary fit and repetition

**Review when:** A word is needlessly abstract, repeatedly used without purpose, or mismatched with the source's register. A vocabulary match alone does not justify replacement.

**Vocabulary prompts:** Read `<skill-dir>/references/vocabulary-by-era.md` for English candidates and possible alternatives. Treat its lists as review aids, not forbidden words or a classifier of model eras.

Use a plain alternative when it preserves the precise meaning and voice: “use” may work for “leverage,” and “help” may work for “facilitate.” Keep a technical or formal term when it is the right term. Do not cycle synonyms to raise lexical diversity, or delete a connective that carries a needed logical relationship.

### 3. Copula avoidance

**Review when:** An elaborate linking phrase makes a straightforward statement harder to read without adding meaning.

**Candidates:** serves as, stands as, marks, represents, boasts, features, offers.

“Is,” “are,” or “has” may be clearer, but these verbs are not interchangeable in every context. Preserve distinctions between identity, temporary function, representation, and possession. Keep the original construction when it expresses such a distinction.

**Before:** “Gallery 825 serves as LAAA's exhibition space.”
**After:** “Gallery 825 is LAAA's exhibition space.”

### 4. Participial phrase overuse

**Review when:** Stacked dependent clauses obscure the actor, sequence, cause, or main point. An English “-ing” ending alone is not a defect.

**Vocabulary prompts:** See Pattern 4 in `<skill-dir>/references/ai-tells-lexicon.md`.

Split a crowded sentence when that makes its relationships clearer. Keep every substantive clause and its causal or temporal role. Delete a tail only if it is content-free or duplicates information already retained; preserve an informative participial phrase that reads clearly.

**Before:**
> The team redesigned the dashboard, streamlining the workflow and enabling users to access reports faster, ultimately contributing to higher satisfaction scores.

**After:**
> The team redesigned the dashboard. The redesign streamlined the workflow, let users access reports faster, and contributed to higher satisfaction scores.

### 5. Rule of three

**Review when:** A grouping repeats the same point or adds an unnecessary rhetorical preamble. Three distinct requirements, examples, or arguments are legitimate.

Keep every substantive enumeration member. Do not reduce, expand, or split a list merely because it has three items. A complete list may remain unchanged; removing a redundant introduction is optional when it improves flow.

**Before:** “The workshop covers three areas: backups, access controls, and recovery.”
**After:** “The workshop covers backups, access controls, and recovery.”

All three topics remain. The list length is not the editing target.

### 6. Formulaic transitions

**Review when:** Repeated bridge phrases interrupt an already clear connection or introduce a relationship the text does not support.

**Vocabulary prompts:** See Pattern 6 in `<skill-dir>/references/ai-tells-lexicon.md`.

Remove or shorten an unnecessary transition. Keep transitions that clarify contrast, consequence, sequence, or a topic change. Do not remove “however” or “therefore” simply because it appears in a list; confirm that the logical relationship remains clear.

### 7. Conclusion bloat and “Overall” opener

**Review when:** A conclusion repeats nearby content without helping navigation, synthesis, or the genre's purpose.

**Vocabulary prompts:** See Pattern 7 in `<skill-dir>/references/ai-tells-lexicon.md`.

Condense redundant restatement. Keep useful summaries, final qualifications, recommendations, and commitments. A final paragraph need not introduce new information, and “Overall” is not an automatic defect. Never manufacture a next step, date, or link to replace a recap.

**Before:**
> The new API is faster, more reliable, and easier to use. Overall, it is faster, more reliable, and easier to use.

**After:**
> The new API is faster, more reliable, and easier to use.

### 8. Didactic disclaimers

**Review when:** An importance marker delays a statement without adding a useful warning or distinction.

**Vocabulary prompts:** See Pattern 8 in `<skill-dir>/references/ai-tells-lexicon.md`.

Remove content-free throat-clearing while preserving the proposition it introduces. Keep a warning, applicability condition, uncertainty statement, or limitation even when it begins with a familiar phrase.

**Before:** “It's important to note that the data shows a declining trend.”
**After:** “The data shows a declining trend.”

## TIER 2: Additional contextual review

Apply these within the requested scope. They use the same definition of an actionable finding as Tier 1.

### 9. Negative parallelisms

**Review when:** Repeated “not just X, but Y” framing adds unnecessary setup to a point that can be stated directly.

**Vocabulary prompts:** See Pattern 9 in `<skill-dir>/references/ai-tells-lexicon.md`.

Keep a genuine contrast, correction, or exclusion. “Not X but Y” and “not just X but Y” have different meanings; preserve what is denied and what is included. Do not turn a contrast into an invented historical shift.

**Before:** “It's not just about writing code; it's about crafting experiences that resonate with users.”
**After:** “This is about writing code and crafting experiences that resonate with users.”

### 10. Synonym cycling

**Review when:** Different labels for the same referent make the reader wonder whether the text means different things.

Use a consistent term or an unambiguous pronoun. Confirm that the labels really refer to the same entity before merging them. Keep distinct technical terms and necessary repetition; do not invent gender, identity, or other attributes when choosing a pronoun.

**Before:** “The protagonist faces a crisis. The main character must then decide. The central figure ultimately chooses to leave.”
**After:** “The protagonist faces a crisis. They must then decide and ultimately choose to leave.”

### 11. False ranges

**Review when:** Repeated “from X to Y” framing obscures categories rather than explaining a useful scale or scope.

**Vocabulary prompts:** See Pattern 11 in `<skill-dir>/references/ai-tells-lexicon.md`.

A list or direct statement may be clearer, but preserve all named groups and the breadth of the claim. Keep real ranges, endpoints, units, and temporal spans. Do not infer which users are typical or which groups have adopted a product from a statement about whom it supports.

**Before:** “The platform helps users from solo developers to enterprise teams, and organizations from startups to Fortune 500 companies.”
**After:** “The platform helps users and organizations, including solo developers, enterprise teams, startups, and Fortune 500 companies.”

### 12. Em dash overuse

**Review when:** Nested or repeated interruptions make a sentence's main clause or relationships hard to follow. An em dash alone, or its frequency without a reading problem, is not an actionable finding.

Keep dashes that fit the language, meaning, and register. In Russian, constructions such as “Москва — столица России” may use a grammatical dash; do not replace it with a hyphen merely to change the punctuation. A user-specified house style can guide typography, but is not evidence of authorship.

**Before:** “The tool — which launched last year — handles deployment — including rollbacks — and monitoring — both real-time and historical.”
**After:** “The tool launched last year. It handles deployment (including rollbacks) and monitoring, both real-time and historical.”

The rewrite clarifies nested relationships while retaining the launch timing, rollback support, and both monitoring modes. It does not establish a ban on dashes.

### 13. Boldface, emoji overuse, and list addiction

**Review when:** Formatting competes with the content or turns a connected narrative into fragments without improving navigation.

Consider whether labels, emphasis, emoji, numbering, or bullets help this audience use the text. Keep useful navigation, parallel lists, requirement sets, and ordered procedures. Numbered items can also be useful for reference even when order is not procedural. Convert a list to prose only when the relationship reads more clearly that way, retaining every substantive item and any dependencies or order. Do not replace an exhaustive enumeration with representative examples unless abridgment was requested.

**Before (optional prose conversion for a short update):**
> - **Speed:** Code generation is significantly faster.
> - **Quality:** Output quality has improved.
> - **Adoption:** Usage continues to grow. 🚀

**After:**
> Code generation is significantly faster. Output quality has improved, and usage continues to grow.

**Before (benefits listed as if they were ordered steps):**
> Key benefits of the migration:
> 1. Reduced latency by 40%
> 2. Simplified the deployment pipeline
> 3. Eliminated the need for manual configuration
> 4. Improved error messages
> 5. Better logging

**After:**
> The migration cut latency by 40%, simplified the deployment pipeline, and eliminated the need for manual configuration. Error messages and logging improved too.

Both examples permit a prose conversion when the surrounding document calls for a brief narrative update. A reference list or scannable summary could keep the list format instead.

### 14. Title case in headings

**Review when:** Capitalization conflicts with the document's intended style or the language's conventions.

Use the requested or established heading style consistently. Sentence case and title case can both be appropriate; neither is an authorship signal in this workflow. Preserve proper names and case-sensitive text.

**Before (document uses sentence case):** “Strategic Negotiations And Global Partnerships”
**After:** “Strategic negotiations and global partnerships”

### 15. Curly quotation marks

**Review when:** Quote or apostrophe typography conflicts with an explicit format requirement or is inconsistent within editable prose.

Follow the target format and language. Keep curly quotes in prose when appropriate; Markdown does not itself require straight quotes. Never change protected code, structured data, citations, or quoted source text to normalize typography. A straight-versus-curly preference is a format choice, not a detector rule.

**Before (ordinary prose in a field requiring ASCII punctuation):** We’re ready.
**After:** We're ready.

### 16. Chatbot artifacts, sycophancy, and knowledge-cutoff disclaimers

**Review when:** Conversational scaffolding or chat-interface residue has been carried into editable prose where it does not serve the requested purpose.

**Vocabulary prompts:** See Pattern 16 in `<skill-dir>/references/ai-tells-lexicon.md`.

Remove an irrelevant greeting, offer to continue, or praise wrapper. Keep such wording when it belongs to the requested message genre. Preserve substantive uncertainty, source limitations, and date boundaries rather than treating every disclaimer as disposable. A wrapper does not by itself establish how the text was authored.

**Before:** “Great question! Here is the setup overview: install the package, then configure the service. Let me know if you'd like more detail!”
**After:** “Install the package, then configure the service.”

**Paste cleanup:** Identify what a suspected artifact does before removing it. A user-identified copy-button label outside the document can be discarded; the same words inside a quotation, code block or instructions may be substantive. Remove only the clearly extraneous span within the authorized edit scope. A section-only request does not authorize cleanup elsewhere unless the user also includes it.

When surrounding text must remain exact, removing a wrapper line does not also authorize trimming neighboring blank lines or changing section separators. Preserve those bytes unless they are explicitly included in the editable/removable span.

- Keep real citations and reference markers exactly, including unresolved or unusual-looking ones. Token shape alone does not establish that a citation is disposable. Leave an ambiguous marker intact, or flag it outside the rewrite when useful.
- Preserve quoted examples of artifacts, code, links and their complete URL targets, including tracking/query parameters. Do not repair a suspected source URL by guessing.
- Do not strip Unicode or normalize the whole document to remove residue. Emoji, joiners, combining marks and language-specific punctuation can be meaningful. Edit only an identified extraneous span.

For example, in “The literal token `citeturn0search0` is an example. 👩‍💻”, the quoted token and emoji stay. See the mixed-content before/after in [full-example.md](full-example.md).

### 17. Filler phrases

**Review when:** Wording adds no information or unnecessarily delays the operative statement in the intended register.

**Vocabulary prompts:** See Pattern 17 in `<skill-dir>/references/ai-tells-lexicon.md`.

Shorten only where the result preserves purpose, obligation, condition, scope, and emphasis that matters. A stock phrase can carry information; do not cut it on sight or replace a generic recommendation with a specific one absent from the input.

**Before:** “In order to fully realize the potential of these tools, it is worth noting that teams should align with best practices.”
**After:** “Teams should follow best practices to fully realize these tools' potential.”

### 18. Excessive hedging

**Review when:** Several expressions redundantly encode the same uncertainty and make a claim difficult to follow.

Simplify redundant hedge wording while preserving the degree and source of uncertainty. Distinct qualifications may need several clauses: a claim can be tentative, restricted to a population, and dependent on a condition at the same time. There is no hedge-count target. Do not change “might” into “probably” or “does” to sound more confident.

**Before:** “It could potentially be argued that this might possibly have some positive effect on outcomes.”
**After:** “This might have a positive effect on outcomes.”

### 19. Generic positive conclusions

**Review when:** A closing flourish repeats an earlier assessment or obscures the actual ending.

**Vocabulary prompts:** See Pattern 19 in `<skill-dir>/references/ai-tells-lexicon.md`.

Remove content-free or redundant closing language. Keep a substantive outlook, its speaker, and its uncertainty. Do not add personal skepticism, optimism, a release date, or a next step that the input did not supply.

**Before:** “In conclusion, the team says the future of AI-assisted development looks bright, although its benefits remain uncertain.”
**After:** “The team says it is optimistic about AI-assisted development, although its benefits remain uncertain.”

### 20. Hyphenated compound modifiers

**Review when:** A crowded modifier chain is hard to parse, or hyphenation conflicts with the intended style or meaning.

Use hyphenation to support clarity and the source's language and register. Consistency is not a defect. Do not introduce inconsistent punctuation to imitate a presumed human habit. Restructuring a modifier chain can help, but preserve each property and keep technical names unchanged.

**Before:** “The well-established, high-quality, open-source library handles authentication.”
**After:** “The library is well established, high quality, and open source. It handles authentication.”

This is an optional readability edit, not a requirement to change correctly hyphenated modifiers or avoid a three-item grouping.

### 21. Pronoun avoidance

**Review when:** Repeating a full noun phrase burdens the passage and a shorter reference would remain unambiguous.

Use pronouns where the reader can identify their referent. Keep or restore names when multiple actors, paragraph breaks, or reordered sentences would otherwise create ambiguity. Repetition is preferable to an unclear reference.

**Before:** “The machine learning model processes input data. The machine learning model then generates predictions. The machine learning model can also be fine-tuned.”
**After:** “The machine learning model processes input data. It then generates predictions and can also be fine-tuned.”

### 22. Structural monotony

**Review when:** Repeated templates bury distinct facts, a paragraph has no clear purpose, or organization obscures the relationship between ideas. Similar sentence or paragraph lengths alone are not a problem.

During full treatment, review:
- **Paragraph purpose:** What does each paragraph contribute? Remove only empty setup or redundant restatement; retain distinct claims and qualifications.
- **Section templates:** Do repeated openings and closings help navigation, or merely repeat the heading? Keep consistent headings and useful genre conventions.
- **List necessity:** Would a list make parallel requirements easier to use, or would connected prose clarify a narrative? Preserve members, dependencies, and required order.
- **Logical order:** Keep prerequisites before dependent actions and qualifications attached to the claims they limit. Do not invent causal links when moving material.
- **Referent continuity:** After a move or merge, can the reader still identify every actor and pronoun? Restore an existing name if needed.

For local repairs, restructure only to address an identified organizational problem. An explicit full rewrite also authorizes regrouping and re-expressing connected facts in grammatical prose: use the source's actors, actions, conditions, qualifications and paragraph purposes rather than treating sentence frames as protected. A source sentence need not be defective to be reformulated. Light passes and section-only requests retain their limits.

Check moved claims and conditions against the complete original, including late qualifications, attribution, action order and referents. Keep strong existing constructions when useful; no minimum amount of change, paragraph count, sentence-length distribution, fragment quota or deliberately uneven section layout applies.

**Before:**
> ### Authentication
>
> This section describes authentication. The API handles authentication through OAuth 2.0. It supports both client credentials and authorization code flows. Tokens expire after one hour and can be refreshed automatically.
>
> ### Rate limits
>
> This section describes rate limits. The rate limiter enforces per-endpoint quotas. It uses a sliding window algorithm for accurate counting. Exceeded limits return a 429 status code with retry headers.

**After:**
> ### Authentication
>
> The API uses OAuth 2.0 with both client credentials and authorization code flows. Tokens expire after one hour and can be refreshed automatically.
>
> ### Rate limits
>
> The rate limiter uses a sliding window algorithm for accurate counting and enforces per-endpoint quotas. Exceeding a quota returns a 429 status code with retry headers.

The headings retain navigation. The rewrite removes openings that merely repeat them and combines related facts without dropping either authentication flow, refresh possibility, quota scope, counting method, status code, or retry headers. The two sections may remain similar in length.

### 23. Colon-itis

**Review when:** Repeated introductory setups delay the substantive points or make relationships harder to follow.

A colon can clearly introduce an explanation, list, or example. Keep it when useful. Fold an empty setup into the statement only when the logical relationship and all supplied information survive; no colon-count target applies.

**Before:** “The reason is simple: the API was never designed for real-time use. Consider the following: each request takes 200ms.”
**After:** “The API was never designed for real-time use. Each request takes 200ms.”
